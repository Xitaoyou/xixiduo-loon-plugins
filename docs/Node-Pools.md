# 免费节点筛选与历史状态

作者：西西多。手机只订阅精选结果，不导入庞大的候选列表。

## 来源与队列

每小时检查 [pixelor/ecfg](https://github.com/pixelor/ecfg) 的 GitHub 提交，变化后完整检测；未变化时每六小时完整复测。读取同一提交的六个 ecfg6 文件，按 Git blob 摘要验证备用镜像，不混合缓存，不使用 APK 内嵌的 Gitee 令牌。

支持 VMess、Hysteria2（含两个 URI 别名）、VLESS TCP/WS 与 Reality/Vision、Trojan TCP/WS、兼容的 SS AEAD/2022 和 Simple Obfs。只转换三端能保留的连接参数，证书验证保持开启，未知必需参数明确拒绝。

完整连接参数去重，忽略名称；同地址不同凭据不会误合并。活跃候选上限 2000；池满每轮按入队顺序额外试测最多 200 个配置。正常落选项回队尾，不当作连接失败。历史配置不会因为上游缺失而立即删除，但必须重新实测才能继续精选。明确受限的配置移除连接内容，只保留指纹和来源记录，不重写 Git 历史。

## 稳定精选

- 最多 30 个不同出口，US/JP/SG/DE 各预留一个合格名额，其余全球选优。
- 当轮基本 HTTPS 延迟 ≤1000ms、下载中位数 ≥10Mbps、至少两项 AI 探测通过，已知风险排除，未知质量允许。
- 正式稳定还须：至少三轮跨越 12 小时，最近三轮有效下载中位数 P25 ≥10Mbps，最近七天有效基本连通成功率 ≥95%。
- 前 12 小时使用观察期临时结果，之后不满足稳定条件就不发布，不保证凑满名额。旧测速版本不能混入历史。
- 按保守吞吐 P25 × 成功率选优，再参考延迟波动、延迟、IP 质量；推荐只从最终精选中选择，各组主备出口不同。

## 检测与恢复

每片最多 50 个节点，最多八片并行，每片四个并发。Cloudflare/Google/Apple 分别三次轻量探测；至少两个健康提供方各成功两次，才有有效延迟。站点控制探测失败时停止或排除该站，不批量处罚节点。

AI 合格候选的 IP、流媒体和详细测速在同一台云端机器完成；预热后 3 × 8MiB，最多两节点并发。不按基础延迟提前截取详细候选。记录机器地区、直接下载基线和版本；前后基线异常则整轮不发布。更换出口、测量版本或机器所在国家不混用性能历史。

完全失败立即退出精选并隔离，约 30 分钟、两小时复测，三轮确认失败才冷却七天。定时任务每 15 分钟检查到期复测，不意味着每 15 分钟全池测速；GitHub 可能延迟调度。连续两轮有效延迟 >1000ms 改为每日低频复测；未知延迟既不当零也不重置超标计数。AI 不足两项、下载不足门槛都不会进入精选。

状态保存在公开的 [pool-state 分支](https://github.com/Xitaoyou/xixiduo-loon-plugins/tree/pool-state)，包含公共连接配置、七天观察历史、队列、隔离/冷却记录。状态读取错误必须停止，不能当作空池初始化；不接入私人机场。

## 发布与运行

分片缺失、轮次错配、核心失败、直接网络基线异常或不少于 20 个节点且至少 95% 同时失败时，保留上一完整版本。上游失败仍可复测可信历史，记录 source_error。成功完成后用 Git 原子推送一起更新精选和状态分支；任一分支冲突，两者均不更新。失败原因看 [Actions](https://github.com/Xitaoyou/xixiduo-loon-plugins/actions/workflows/free-nodes.yml)。合格结果为空时允许发布空订阅，不伪造可用性。

Actions → Update free nodes → Run workflow：`force` 强制完整复测；`export_only` 仅转换现有结果，不检测也不改时间。工具顺序 prepare → shard → measure → finalize → publish，不能跳过或缺片强行发布。
