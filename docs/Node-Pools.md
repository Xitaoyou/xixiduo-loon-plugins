# 候选池与精选池

作者：西西多。候选池积累历史可用配置，精选池供 Loon、Clash/Mihomo、Shadowrocket 导入。

## 来源与协议

每小时检查 GitHub 上游提交版本；有新版本时完整检测，无变化时每六小时复测。读取同一提交下六个 ecfg6 文件，校验 Git blob 摘要后解密。raw、jsDelivr、CDN、files 只作为同一内容的备用地址，不混合旧缓存，不使用 APK 中的 Gitee 令牌。

覆盖 VMess、Hysteria2（两个 URI 别名）、VLESS TCP/WS 与 Reality/Vision、Trojan TCP/WS、兼容的 SS AEAD/2022 及 Simple Obfs。三个客户端的连接参数同步转换；证书验证保持开启，不支持的传输、指纹或必需参数会记录拒绝原因。浏览器指纹仅映射三端共同支持的 Chrome/Safari 家族；不声称不同核心的指纹字节完全一致。

按完整连接参数指纹去重，名称和参数排列不参与；同地址不同凭据不会误合并。上游没有继续列出，不等于节点失效；历史配置继续复测。明确受限标记会移除同凭据历史配置。

## 状态与淘汰

公开的 [pool-state 分支](https://github.com/Xitaoyou/xixiduo-loon-plugins/tree/pool-state) 保存池状态，包含公共来源的连接配置，不提供候选池手机订阅，也不接入私人机场。

- 活跃候选上限 2000，其他配置进入持久待测队列。池满每轮额外试测最多 200 个，按未测试/上次排队测试时间轮转。
- 超容量时按国家轮流保留，国家内优先 AI 通过数、IP 质量、基本延迟和稳定编号；正常落选配置回待测队列。
- 每个节点请求两个独立 HTTPS 检测地址，共三次轻量探测。全部失败时当轮淘汰，冷却七天；重新发现也不能提前导入。
- 至少两次成功样本取请求耗时中位数。超过 1500ms 当轮不入精选，连续两次有效检测轮超标后淘汰并冷却七天。只有一次成功则延迟未知，不进入精选，保留候选。
- 连通合格但 AI 不足两项通过的节点继续留在候选池。质量未知允许参与精选，已知风险不参与；既有下载、纯净 IP 和流媒体推荐条件保持不变。
- 候选池可能因淘汰变小，不保证一直增长。

## 检测与发布

每片最多 50 个节点，最多八片并行，每片四个并发。先做基本连通和延迟，再对合格项检测 AI，AI 至少两项通过后查询质量、检测流媒体并做下载测速。

检测核心启动/运行失败、检测站整体不可达、分片缺失或轮次不匹配时整轮不发布；不少于20个节点且95%以上同时确认失败时也触发整体熔断，防止大面积误淘汰。故障信息在 [Actions](https://github.com/Xitaoyou/xixiduo-loon-plugins/actions/workflows/free-nodes.yml) 中查看。

上游暂时不可用但已有历史池时，仍按复测周期检测历史节点，来源版本保持上次已验证版本，并记录 source_error；不接受未经版本验证的新内容。首次初始化没有可信来源时停止。

若所有连通节点都不满足精选条件，候选状态仍正常保留，精选发布为空，不伪造可用节点。

完成整轮后，精选文件和 pool-state 分支使用 Git 原子推送一起发布；任一分支冲突或推送失败则两者都不更新。所有结果使用同一轮次编号，状态统计中记录上游提交、新增、重复、拒绝原因、活跃/待测/冷却数量和本轮检测数量。

精选规则及导入地址见 [免费节点说明](Free-Nodes.md)。只有当轮符合条件的活跃候选进入精选；每国最多四个不同出口，保留各类主备推荐和刷新时间。三种格式从同一结果导出。

## 手动运行

Actions → Update free nodes → Run workflow。`force` 强制完整复测；`export_only` 仅转换已有精选，不修改检测时间或候选状态。不要同时启用两个选项；export_only 优先。

本地检查：`python -m unittest discover -s scripts/free-nodes -p 'test_*.py'`。池工具分为 prepare、shard、finalize、publish，需按完整工作流运行，不能缺片强行发布。
